# 请求执行流程（教学篇）

> 三条链路逐段拆解：① 服务间能力调用（解读为例）② C 端智能体对话 ③ 工具查询真实数据。

## 链路一：服务间能力调用（以"报告解读"为例）

用户在小程序点"AI 解读报告"后发生的事：

```
小程序 ──▶ 网关(8080) ──▶ health(Java) ──Feign──▶ ai-service(8091) ──▶ 智谱 GLM
                JWT 鉴权      聚合报告+指标      /internal/ai/report-interpret
```

### 第 1 步：health 侧聚合（Java）

`ReportInterpretationService` 把报告元数据 + 指标列表组装成**结构化 DTO**（不是拼好的字符串）——这是关键设计：**Java 不写 prompt，只发数据**。

### 第 2 步：Feign 跨语言调用

health 的 `AiApi`（Feign 接口）POST 到 `http://star-site-platform-ai:8091/internal/ai/report-interpret`。Feign 是 Java 的声明式 HTTP 客户端——接口上打注解，调用像本地方法。这里它调的其实是个 Python 服务，**但 Feign 不知道也不关心**（HTTP + JSON 就是两种语言的公共语言）。

### 第 3 步：Pydantic 自动校验（api/internal.py）

FastAPI 收到请求后，JSON body 自动反序列化为 `InterpretRequest`（Pydantic 模型）：类型不符/缺必填字段直接 422，**不需要手写校验代码**。

### 第 4 步：LCEL 链执行（agents/report_interpret.py）

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM_PROMPT),          # 角色约束："你是家庭健康助手…300字以内"
    ("human", "报告：{report_desc}…{indicators}"),
])
chain = prompt | chat_model() | StrOutputParser()
text = await chain.ainvoke({...})       # 结构化数据填进模板 → 调模型 → 取文本
```

`|` 管道符把三步串成链（LCEL = LangChain 表达式语言），类似 Java Stream 的 `map→collect`。`ainvoke` 是异步调用——FastAPI 的事件循环在等待模型响应时可以处理其他请求（**不占用线程**，这是 Python async 的核心价值）。

### 第 5 步：结果包装返回

`r_ok({"text": "..."})` 包成 R 信封原路返回。health 侧拿到文本落库缓存（同一报告不重复花钱），再经网关回到小程序。

**全链路出错怎么办**：模型超时 → Python 侧 catch 后返回 `r_fail(503, retryable=True)` → Java 侧 RpcClientAspect（AOP 切面）自动检查 code 非 0，翻译成标准异常 → 翻译成 503 业务提示。每一层都有自己的兜底，没有一层"裸抛"。

## 链路二：C 端智能体对话（SSE 流式）

用户在对话页问"我们家净资产多少？"：

```
小程序 ──POST /api/ai/agent/chat──▶ 网关 JWT ──▶ ai-service
                                                  │ SSE 流式返回
小程序 ◀──event: token───...───done────────────────┘
```

### 身份链路（安全核心）

1. 网关验证 JWT 有效性后放行（但网关不告诉下游"用户是谁"）；
2. ai-service 的 `api/open_agent.py` **自己再验签一次**：用与网关相同的 HS256 密钥解析 token，从 `sub` 字段取出 memberId；
3. memberId 写入 `ContextVar`（上下文变量）——**不是**放在 prompt 里，模型无法伪造身份；
4. 工具执行时从 ContextVar 读出身份，用它去查数据（查的永远是你自己的家庭数据）。

### SSE 流式是什么

Server-Sent Events——服务器可以**分多次**往同一个 HTTP 响应里推数据。模型生成是逐 token 的，流式让用户看到"正在打字"的效果而不是干等 30 秒。事件类型：`status`（正在调用工具 X…）/ `token`（一段增量文本）/ `done`。

### ReAct 循环（agents/assistant.py）

智能体不是"一次调用"，而是**循环**：

```
用户问题 ──▶ 模型思考（ReAct）
              │ "我需要先查资产负债表" ──▶ 调工具 get_balance_sheet ──▶ 拿到真实数据
              ▼
            模型继续思考
              │ "拿到数据了，组织回答" ──▶ 生成最终回复 ──▶ 输出
```

每轮工具结果都拼回对话历史再喂给模型，直到模型给出不含工具调用的最终回答。这个循环由 LangGraph 的 `create_react_agent` 预制实现。

## 链路三：工具查询真实数据（tools/）

智能体决定调 `get_balance_sheet` 后：

```
工具函数(同步) ──asyncio.run──▶ internal_get(异步HTTP)
                                   │ 1. 查 Nacos：star-site-biz-finance 的健康实例
                                   │ 2. GET http://star-finance:8088/internal/finance/balance-sheet?memberId=12
                                   │ 3. 拿到 R 信封
                                   ▼
                              返回格式化文本（"总资产 X 元，净资产 Y 元"）
```

三个教学点：

1. **服务发现缓存**：Nacos 查询结果缓存 10 秒（避免每次调用都查注册中心）；
2. **同步工具包异步调用**：LangChain 工具协议是同步函数，内部用 `asyncio.run()` 起临时事件循环执行异步 HTTP；
3. **工具输出是给模型看的文本**：不是 JSON 而是"总资产 2,800,157.35 元…"这样的人类可读句子——模型理解自然语言比理解嵌套 JSON 更可靠。

## 沙箱模式下的链路（无 key 环境）

同一个入口，`settings.effective_mock` 为 True 时：能力链短路返回【沙箱模拟】固定数据；智能体降级为 FakeChatModel 简化图（ReAct 需要真模型的 bind_tools 能力）。**链路形状不变，只是"模型"这个零件被换成了假件**——这就是依赖倒置的好处。
