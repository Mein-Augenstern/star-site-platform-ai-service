# 配置与部署（教学篇）

> 环境变量清单、Docker 运行方式、沙箱开关、以及"改一个配置就能换模型厂商"的操作路径。

## 配置哲学：12-Factor 第三条

**所有配置经环境变量注入，代码零默认密钥**。这意味着同一个镜像可以在开发/测试/生产跑出不同行为，不需要改代码重新构建。

配置实现在 `app/config.py`：`dataclass(frozen=True)` + 模块级单例 `settings`。`_env()` 辅助函数统一处理"空串视为未设置"（Docker 里 `KEY=` 很常见）。

## 环境变量全表

### 服务与注册

| 变量 | 默认 | 说明 |
|---|---|---|
| `SERVICE_NAME` | star-site-platform-ai | Nacos 注册的服务名（Java 侧按此名发现） |
| `AI_PORT` | 8091 | HTTP 监听端口 |
| `NACOS_SERVER_ADDR` | 127.0.0.1:8848 | 注册中心地址（Docker 内用容器名 star-nacos:8848） |
| `NACOS_NAMESPACE` | public | 命名空间（环境隔离） |
| `NACOS_REGISTER_IP` | 127.0.0.1 | **注册 IP——Docker 必须填容器名 star-ai**（Java 的 LB 才解析得到） |
| `NACOS_GROUP` | DEFAULT_GROUP | 分组 |

### 安全

| 变量 | 默认 | 说明 |
|---|---|---|
| `JWT_SECRET` | 本地开发默认值 | 与网关/Java 共享的 HS256 密钥；`/api/ai/**` 自行验签用。**生产必须注入** |

### LLM

| 变量 | 默认 | 说明 |
|---|---|---|
| `AI_LLM_BASE_URL` | 智谱官方地址 | OpenAI 兼容端点；换厂商只改这里 |
| `AI_LLM_API_KEY` | 空 | **空 = 自动沙箱模式** |
| `AI_LLM_MODEL` | glm-4.5-air | 文本模型（解读/诊断/对话） |
| `AI_LLM_VISION_MODEL` | glm-4v-flash | 视觉模型（拍照 OCR 需要"看图"能力） |
| `AI_MOCK_ENABLED` | 未设置 | `true` 强制沙箱；`false` 且无 key 仍回沙箱 |

### 沙箱模式判定（effective_mock）

```
AI_MOCK_ENABLED=true            → 沙箱（强制）
AI_MOCK_ENABLED=false + 有 key  → 真实
未设置 + 无 key                 → 沙箱（自动兜底）
```

沙箱下：能力端点返回【沙箱模拟】标记的固定数据；智能体降级为假模型简化图。**无密钥环境全链路可跑**。

## 换模型厂商操作路径（模型无关的验证）

以智谱 → DeepSeek 为例：

```yaml
# docker-compose.yml 的 ai 服务 environment 段
AI_LLM_BASE_URL: https://api.deepseek.com/v1
AI_LLM_API_KEY: <DeepSeek 的 key>
AI_LLM_MODEL: deepseek-chat
```

`docker compose up -d ai` 重建容器即可。**业务代码零改动**——LangChain 的 ChatOpenAI 兼容所有 OpenAI 协议服务。视觉模型若新厂商不支持，需要确认 `glm-4v-flash` 换成对应的 multimodal 型号。

## 本地运行（开发调试）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt     # 走清华镜像（Dockerfile 内置；本机手动 -i 参数）

# 无 key（沙箱）
uvicorn app.main:app --port 8091
curl localhost:8091/health          # {"status":"UP","mock":true}

# 快速自测（沙箱）
curl -X POST localhost:8091/internal/ai/report-interpret \
  -H 'Content-Type: application/json' \
  -d '{"reportYear":2026,"indicators":[{"name":"收缩压","value":"148","abnormalFlag":1}]}'
```

> 本机 Python 版本注意：LangGraph 等依赖需要 Python 3.10+ 语法（`X | None` 类型标注）；若本机是 3.9，部分模块导入会失败——**本地验证受限时直接用 Docker（3.11）验证**，这是本工程的既定实践。

## Docker 运行（平台形态）

在 `star-site-backend/docker/docker-compose.yml` 里的 `ai` 服务条目：

```yaml
ai:
  build:
    context: ../../star-site-platform-ai-service   # 跨仓构建（注意是 ../../）
    dockerfile: Dockerfile
  environment:
    NACOS_SERVER_ADDR: star-nacos:8848
    NACOS_REGISTER_IP: star-ai        # 关键：容器名而非 127.0.0.1
    AI_LLM_API_KEY: ...               # 真实模式
    AI_MOCK_ENABLED: "false"
    JWT_SECRET: ...
```

常用操作（在 star-site-backend 目录下）：

```bash
docker compose --profile app build ai      # 构建
docker compose --profile app up -d ai      # 滚动重启
docker logs star-ai --tail 50              # 看日志
```

## 排障速查

| 症状 | 原因与处置 |
|---|---|
| Java Feign 报"无可用实例" | ai 没注册上 Nacos。`docker logs star-ai | grep nacos` 看心跳；常见根因：`NACOS_REGISTER_IP` 没填容器名 |
| 心跳日志显示 code=20404 循环 | 正常自愈过程（心跳发现实例丢失→自动重注册）；持续不恢复查 Nacos 地址可达性 |
| 智能体 401 | JWT_SECRET 与网关不一致（验签失败） |
| 解读返回沙箱标记 | `AI_LLM_API_KEY` 为空或 `AI_MOCK_ENABLED=true` |
| OCR 报"仅支持图片" | 上传的是 PDF——视觉模型只吃图片，按提示截图后拍照 |
| 容器起来但端口不通 | 检查 8091 端口映射与防火墙 |

## 已知踩坑记录（写进注释的教训）

1. **Nacos 心跳 20404 坑**：实例不存在时心跳 HTTP 仍返回 200，但 body `code=20404`——必须解析 body 自行重注册；
2. **ChatOpenAI 空 key 构造即炸**：沙箱环境传占位符 `"mock-key"` 让构造通过，能力层短路永不真调；
3. **compose 跨仓构建上下文**：`context` 相对 docker-compose.yml 所在目录，跨仓要 `../../`。

这些坑在对应源码的注释里都有详细解释——读代码时按图索骥。
